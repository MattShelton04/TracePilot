Agent messaging views

Four ways to show inter-agent communication over time: launches, write_agent messages (including sibling-to-sibling and broadcasts), and read_agent results flowing back. Every view reads the same communication log the app now builds from a session. Hover any message for its text, route and delivery.

Option A

Sequence diagram

New Timeline mode: “Messages”

One lifeline per agent, time running down. Bars show when an agent was working. A slanted arrow means the message waited: it was sent at the top of the arrow and delivered at the tip, so queued messages to busy agents stand out.

Strengths

  • Exact order of every exchange, the way protocols are usually drawn
  • Delivery delay and queueing are visible as slope
  • Broadcasts read as a fan from one point

Limits

  • Wide with many agents (scrolls horizontally past ~8)
  • Long idle stretches waste vertical space unless compressed
Option B

Swimlanes with message arcs

Overlay on the existing Swimlanes view

Agents as rows (indented by nesting) on a shared time axis, with each exchange drawn as an arc from the sender’s row to the recipient’s. Keeps the familiar left-to-right timeline and shows messages in the context of real durations.

Strengths

  • Real durations, so long-running workers look long
  • Scales to many agents vertically
  • Could be a toggle on the existing Swimlanes view

Limits

  • Bursts of messages overlap at session scale and need zooming
  • Message text only fits in tooltips
Option C

Communication graph with scrubber

Agent Tree overlay, and the base for a replay

The agent hierarchy as a graph, with message traffic drawn between agents. Edge weight counts messages; peer edges cut across the tree. Drag or play the scrubber to watch the conversation build up and agents go idle.

Strengths

  • Who talks to whom at a glance, even with large fleets
  • Reuses the Agent Tree layout people already know
  • Scrubbing doubles as a preview of a session replay

Limits

  • Exact ordering needs the scrubber or a hover
  • Aggregated edges hide individual message timing
Option D

Message log

Table in the Timeline tab or a session “Messages” panel

Every exchange as a row: when, who to whom, what kind, how it was delivered and what it said. The plainest view, and the one that reads best when message text matters more than shape.

Strengths

  • Full message text, searchable and filterable
  • Cheapest to build and to keep accessible

Limits

  • No sense of concurrency or duration
  • Hard to spot patterns such as one agent flooding another

Suggested direction

  1. Option A as a new Messages mode in the Timeline tab: it answers “what did the agents say to each other, in what order, and did anything wait?” better than the others.
  2. The Option D log beneath it, sharing the same selection, for reading and filtering message text.
  3. Option C’s peer edges later on the Agent Tree, and its scrubber as the starting point for the replay design.
