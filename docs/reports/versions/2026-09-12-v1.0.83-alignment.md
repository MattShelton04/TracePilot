# Copilot CLI 1.0.83 compatibility alignment

TracePilot now recognizes every persistable event in the official 1.0.83 schema,
retains older payload shapes, and reconstructs multi-turn background agents without
confusing their child conversation loops with the main conversation. This report
records the evidence, fixes, verification and opportunities for additional UI work.

## Baselines and reproducibility

The previous alignment was for 1.0.71 (`e35b4615`, PR #745). Comparing only 1.0.75
with 1.0.83 would have missed five new event definitions and earlier field changes.
The audit therefore compared both 1.0.71 → 1.0.83 and 1.0.75 → 1.0.83.

The rolling local package cache still contained 1.0.75 and 1.0.83. The missing
1.0.71 schemas and agent definitions were recovered from the official npm
[`@github/copilot-win32-x64@1.0.71` package metadata](https://registry.npmjs.org/@github/copilot-win32-x64/1.0.71).
The archive was checked against the registry's SHA-512 integrity value before
extracting only package metadata, schemas and definitions into a separate audit
directory. No installed Copilot binaries were replaced or downgraded.

Archive integrity:

```text
sha512-02kXOBd9CwBbCaztuf71WYWn+uGapCuiaasomN4tcMH3HBVZ4gi3J0ZUoRcgcS80xh81uQyeBHbnUKzb/RE/9A==
```

The version analyzer now accepts `TRACEPILOT_COPILOT_PKG_DIR`, a directory
containing version folders such as `1.0.71/schemas/`. To reproduce an archived
comparison, put both versions' extracted schemas/definitions under that root:

```powershell
$env:TRACEPILOT_COPILOT_PKG_DIR = 'C:\audit\copilot-packages'
pnpm cli versions diff 1.0.71 1.0.83 --json
pnpm cli versions diff 1.0.75 1.0.83 --json
Remove-Item Env:TRACEPILOT_COPILOT_PKG_DIR
```

The analyzer also now detects nested required-field changes, map value changes,
changes within discriminated union branches, and persistence classification
changes. Previously, several of these could look unchanged.

| Schema comparison | 1.0.71 → 1.0.83 | 1.0.75 → 1.0.83 |
| --- | ---: | ---: |
| Added event definitions | 29 | 24 |
| Removed event definitions | 0 | 0 |
| Modified event definitions | 40 | 39 |
| Added RPC methods | 104 | 60 |
| Removed RPC methods | 2 | 2 |
| Modified RPC methods | 61 | 65 |

The schemas contain 110, 115 and 139 event definitions respectively; their
persistable subsets contain 50, 51 and 62. RPC differences are discovery results,
not a claim that TracePilot implements those RPCs. Offline session ingestion is
the compatibility target of this update. Agent definition names did not change.

## Implemented changes

- Added typed payloads and Rust/TypeScript event registry entries for 21 previously
  missing persistable event types, including gaps that predate 1.0.71. Extended
  existing payloads for new nested fields, preserving data through typed parsing.
- Added optional fields for task outcomes, compaction limits and triggers,
  model/configuration details, per-agent accounting, structured reasoning blocks,
  schedules, permissions, assets and fusion events. Existing field names remain
  supported where Copilot renamed permission settings.
- Distinguished the agent instance UUID (`agentId`) from the tool call that
  launched it. Child messages, reasoning and tools attach to the launching turn;
  child turn boundaries, prompts and model changes no longer modify the main loop.
  Envelope `parentId` is an event-chain link, not an agent ownership key.
- Recognized a built-in `task` launch before delayed child logs are flushed.
  A successful background wrapper return no longer means the worker finished.
  Launch failures still finish immediately. Lifecycle/configuration model values
  take precedence over the root wrapper's model.
- Follow-up `write_agent` telemetry reopens a worker; current `read_agent`
  telemetry settles it as idle, failed or cancelled. An initial invocation's
  successful terminal event cannot finish queued follow-ups. Explicit failure and
  cancellation still settle the worker even if no later read occurs. Initial
  invocation counters are cleared when they no longer describe the active work.
- Added idle/cancelled presentation and runtime UUID resolution for agent links.
  Refresh comparisons include old turns with completed agents and incoming turns
  that acquire delayed subagent metadata, so visible status actually updates.
- Reused the conversation state machine for search turn attribution. Child
  boundaries previously caused search links to point beyond the conversation's
  last turn. Analytics version 8 and search extractor version 4 refresh existing
  derived records without changing the original session files.
- Excluded child-scoped context from the main agent's context estimate. The
  standalone TypeScript CLI also excludes child boundaries from its compact root
  conversation view.

## Evidence and validation

The read-only corpus audit covered **383 sessions, 46 CLI versions, 871,170 parsed
events and 5,676 reconstructed subagents**, spanning 0.0.409 through 1.0.83. It
found **zero typed deserialization failures**. One malformed JSONL line was
tolerated. A few out-of-schema telemetry names (`external_tool.completed` and
`model.*` capture events) remain raw `Other` events; they are not claimed as typed
schema coverage. No private session content is committed.

Schema regression fixtures cover every persistable event and its populated
fields in 1.0.71, 1.0.75 and 1.0.83. Recursive assertions check that typed parsing
and serialization preserve the fixture fields, including nested values. These
are representative payloads, not exhaustive tests of every union alternative.
Historical integration fixtures and the wider workspace suite remain in place.
See the [fixture provenance](../../../crates/tracepilot-core/tests/fixtures/versions/README.md).

A controlled 1.0.83 session used only `gpt-5.6-luna` for the main agent and its one
background worker. The main agent launched the worker, waited, sent a follow-up,
then waited again. The persisted log contained just **one** `subagent.completed`
event, even though the worker ran two turns. The second completion was visible in
structured `read_agent` telemetry. A sanitized fixture preserves that ordering.

The real Tauri/WebView2 app was exercised via Playwright CDP using
[`scripts/e2e/copilot-compat.mjs`](../../../scripts/e2e/copilot-compat.mjs). It appends
the sanitized fixture in stages to one temporary session and verifies the visible
sequence **Running → Idle → Running → Idle** without manually refreshing the
conversation. It also checks the subagent panel after its slide-in animation.
The temporary session is removed afterward; existing sessions are not modified.

Additional read-only checks in the actual app opened historical sessions from
0.0.409 (21 turns, 40 tools), 1.0.10 (10 turns, 47 tools), 1.0.71 (93 turns,
252 tools), and 1.0.75 (3 turns, 1 tool). Each conversation rendered with the
backend's turn count. The 1.0.10 and 1.0.71 subagent panels both showed Completed
and retained their model, prompt, output and activity. Screenshots were inspected
after waiting for the panel animation; private screenshots remain outside git.

Validation included 1,421 passing Rust workspace tests (five ignored), Clippy
with warnings denied, 3,205 passing JavaScript/Vue tests, TypeScript checks, the desktop production build,
formatting, file-size limits and documentation links. A separate reviewer
reproduced and reviewed the lifecycle, search and refresh fixes; all actionable
findings were addressed and checked again. The global design-system hex-color
guard still reports two pre-existing fallbacks in `skills-manager.css`, outside
this change. The z-index guard also reports a pre-existing literal in
`FileContextMenu.vue`; spacing has existing warnings. Changed JavaScript/Vue
files pass Biome, and the emoji/backdrop guards pass repository-wide.

## Useful follow-up features

These are opportunities supported by the inspected payloads, not dedicated UI
features delivered by this change. Some fields were already introduced by
1.0.71 but were not fully represented by TracePilot.

| Opportunity | Available evidence | Potential user benefit |
| --- | --- | --- |
| Per-agent usage and model configuration | Shutdown `agentMetrics`, agent configuration, model usage | Attribute work and usage to individual workers, including their reasoning effort and context tier. |
| Explain automatic model selection | Auto-mode resolution/tier switches and fusion routing, phase, handoff and fallback events | Show which model handled each phase and why the route changed or failed. |
| Explain context loss or compaction | Compaction trigger, token limits and post-compaction count; explicit context-clear events | Distinguish automatic compaction, manual clearing and actual context pressure. |
| Explain why work stopped | Task outcome/reason/objective fields and completion receipts with tool outcome counts | Separate task completion, interruption and failure from a normal assistant turn ending. |
| Scheduled work and permissions history | Schedule create/cancel/rearm, objective changes and renamed permission modes | Show what will run again and which permission policy applied at each point. |
| Tool discovery and richer artifacts | `tool_search.activated`, binary assets and canvas metadata | Explain newly available tools and surface generated artifacts with provenance. |

RPC additions also expose persisted-event filtering by agent, queue management,
rewind previews and richer usage queries. Those are candidates for a future live
integration; their presence in the internal schema is not a stability guarantee.
Ephemeral model-call, cache and sandbox diagnostics cannot generally be recovered
from an ordinary persisted session log alone.
