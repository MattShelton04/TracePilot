# Copilot CLI 1.0.91 compatibility alignment

TracePilot now recognizes every persistable event in the official 1.0.91
schema (74 of 74, up from 62), keeps older payload shapes, and handles the new
deduplicated skill receipts in Skills analytics, the conversation and the
Context estimate. Real logs also showed three ways a session could stop being
indexed permanently; all three are fixed.

## Baseline and reproducibility

The previous alignment was [1.0.83](2026-09-12-v1.0.83-alignment.md)
(`c6c43630`, PR #811). The local package cache still held 1.0.80, 1.0.83, 1.0.86,
1.0.88 and 1.0.91, so the comparison needed no archived schemas:

```powershell
pnpm cli versions diff 1.0.83 1.0.91
pnpm cli versions coverage
```

| Schema comparison | 1.0.83 → 1.0.91 |
| --- | ---: |
| Added event definitions | 18 |
| Removed event definitions | 3 (`factory.run_*`, renamed to ephemeral `workflow.run_*`) |
| Modified event definitions | 34 |
| Added / removed / modified RPC methods | 106 / 16 / 60 |

The schemas define 139 and 154 events; their persistable subsets contain 62 and
74. RPC differences are discovery results only; offline session ingestion remains
the compatibility target.

`schema_v1_0_91.jsonl` is generated by
[`copilot-schema-fixture.mjs`](../../../scripts/fixtures/copilot-schema-fixture.mjs),
which reproduces the conventions of the earlier hand-generated fixtures. Running
it again regenerates the committed file byte for byte.

## Schema changes handled

- **New persisted events.** These are `skill.invoked_ref`,
  `skill.context_delivered(_ref)`, `session.permission_recovery`,
  `session.model_deselected` and `session.fusion_change_checkpoint`, plus six
  `permission.*` authorization receipts. The schema marks the permission
  receipts experimental and "historical decode-only", so they are typed for
  lossless parsing but not interpreted.
- **New optional fields.** These include turn `parentToolCallId`,
  `originatingMessageId`, subagent `taskModelSource`/`modelSelectionSource`/
  `workflowRunId`, and tool `toolTitle`/MCP config source. Also added are
  `shellExecution`, `responsesReasoning`, task and permission `blocker`,
  permission `decisionSource`/`recoveryEpisodeId`, fusion `hint`/`judgeModel`/
  `repairModel`/`critics`, and billing `model`. Typed parsing preserves every
  field in the 1.0.71, 1.0.75, 1.0.83 and 1.0.91 contracts.
- **Widened enums** (`fast` auto tier, model-change sources, `workflow`
  permission kinds, `paused` workflow notifications) are stored as strings or
  raw JSON and needed no change.

### Deduplicated skill receipts

A controlled 1.0.91 session (auto model, a two-line project skill, invoked
once and again after a resume) showed the new shape:

1. The first call writes an inline `skill.invoked` with `content`.
2. The repeat writes `skill.invoked_ref` with `contentId`
   (`sha256:` of the UTF-8 body) and `contentLength`, but no body.
3. **Every** invocation is followed by `skill.context_delivered_ref`, parented
   to the invocation, adding the real `<skill-context>` prefix (base directory
   and related-file list) and suffix around the referenced body.

Before this change the repeat was an unknown event. Skills analytics counted it
only as a tool-call fallback without path, hash or token estimate. The Context
estimate counted only the bare body, missing the wrapper; a real 1.0.86 session
had a 7,079-character body inside a 16,036-character delivered context. The
parser now resolves references while streaming. It hashes inline bodies lazily,
only once a reference appears. The resolved body feeds turn reconstruction,
Skills analytics and the Context estimate, and the delivered wrapper is counted
once in place of the body. Analytics extraction version 16 refreshes existing
rows. A sanitized copy of the probe is the `v1_0_91_skill_refs.jsonl` fixture.

## Real-log findings

TracePilot logs from this machine and a second machine were reviewed with the
real Rust parser over all 404 local sessions (2.6 GB).

| Finding | Cause | Change |
| --- | --- | --- |
| `session.shutdown` "invalid type: floating point `528375599.99999994`, expected u64"; session never re-indexed | The schema types `totalNanoAiu` as `number`; 1.0.86+ can write fractional sums | Nano-AI-unit fields accept integer, float or numeric-string values and round to the nearest unit |
| "unexpected end of hex escape"; 9,928-event session never re-indexed | Shell output truncated inside an emoji left a lone UTF-16 surrogate (`\ud83d`). JavaScript accepts it; serde_json rejects the line | After a parse failure, unpaired surrogate escapes become U+FFFD and the line is retried |
| "Session snapshot not indexed; retaining previous data", repeated for the sessions above | A complete snapshot is required, so either failure kept old data and re-parsed the file on every refresh | Resolved by the two fixes; 0 of 404 local sessions remain blocked (2 before) |
| Unedited skills used with a current CLI marked "Changed since used" (found during the live check) | Since about 1.0.48, `skill.invoked.content` is the body without frontmatter (leading whitespace trimmed), while the installed fingerprint covered the whole `SKILL.md` | Installed skills also expose a body fingerprint; either match means unchanged. Locally, only the one genuinely edited skill remains flagged |
| `[alerts] Failed to register notification click handler` at every launch | The desktop notification plugin implements only notify/permission commands | Treated as unsupported and logged at debug |
| `[ERROR][tracing::span] jsonrpc_read_loop;` on each successful SDK connect | The SDK scopes loops with `error_span!`; the log bridge prints span lifecycle at that level | `tracing::span` target disabled |
| `Background ensureIndex failed {"code":"ALREADY_INDEXING"}` | Overlap with an indexing pass that is already running | Logged at debug |
| 4 errors every 5 s for about 6 minutes: `Session not found` from detail refresh and running checks | Auto-refresh kept polling an open session whose directory was deleted | Auto-refresh pauses on `Session not found`; a manual refresh retries and resumes it |
| `[ERROR][commands::sdk] Copilot SDK bridge is disabled by user preference` | `#[instrument(err)]` logged the expected refusal at ERROR | Logged at debug; other connect failures remain errors |

Slow-query warnings for `session_agent_runs WHERE session_id = ?` occurred during
heavy reindexing; the primary key already serves that lookup, so they reflect
write contention, not a missing index. The `ErrorBoundary` and `formatShellInput`
errors came from development hot reloads (`127.0.0.1:1420`). Occasional WebView2
`failed to create webview` errors occur at process start when another instance
is launching, and SDK `connection refused` errors are genuine connection failures;
neither changed.

The second machine's `no such column: r.messages_sent` errors (Agents page and
720 failed reindexes) came from a development build between 21 and 24 September,
which recorded index migration 20 as session-store enrichment (#845, reverted in
#846) before #851 reused version 20 for agent messaging. Released builds never
shipped the enrichment migration, so no fix is included. **Never reuse a
migration version that has run on main**, even after a revert.

Out-of-schema `model.*` capture events (for example `model.turn_started`) still
appear as unknown types and remain raw events, as in 1.0.83.

## Validation and performance

- Rust workspace: 1,735 tests pass; Clippy (warnings denied) and rustfmt clean.
- JavaScript/Vue: 4,092 tests pass; typecheck, Biome, file-size, public-API checks pass.
- New regressions: 1.0.91 schema contract; body-only skill fingerprints;
  skill-reference resolution with a real content ID; repeated invocation attachment, folding and analytics from the probe
  fixture; delivered-wrapper Context estimate; and a snapshot with a fractional
  total and a lone surrogate, which previously failed.
- Criterion `parsing` benches (100–5,000 events) against `main`: no
  statistically significant regression. Whole-corpus parse plus derivation
  (turns, skills, Context) over 404 real sessions: about 8.8–9.4 s and
  3.3–3.7 s per pass on both trees, within run-to-run noise.
  Lone-surrogate repair runs only after a line fails to parse; reference hashing runs
  only when a session contains references.
- The analytics version bump causes one background re-extraction of each indexed
  session on first launch, without blocking the UI.

## Live check

The real Tauri/WebView2 app (debug Rust build, configured sessions and index)
was exercised through the Playwright CLI:

- The v16 re-extraction covered 612 indexed sessions in 92 s (`reindex_sessions`)
  on the debug build. Both previously stuck sessions were indexed, and the log had
  no ERROR or snapshot-blocking parse warnings. It also had no notification,
  `tracing::span` or `ALREADY_INDEXING` noise.
- The probe session shows both `skill` calls with the resolved body. Skill usage
  reports 2 event-backed uses with token estimates and no false drift notice;
  the Skills manager flags only the genuinely edited skill.
- The fractional-total session's Metrics show 1.39 AI Credits with per-model usage.
  The 9,928-event session with a lone surrogate opens all 438 turns.
- The Context view for a 1.0.86 skill session and the Agents explorer render with
  no console errors.
