# TracePilot desktop usability audit — 12 September 2026

Status: in progress. This document records observed coverage, not a claim of exhaustive testing.

## Environment and safeguards

- Baseline `08b4e5e1`; dedicated branch `codex/desktop-usability-audit`; original working tree clean.
- Automation PR [#812](https://github.com/MattShelton04/TracePilot/pull/812) is merged and already included. Reuse its pinned Playwright CLI and `pnpm app:start` workflow.
- Primary environment: Windows Tauri/WebView2 with real Rust IPC. Viewports are CSS pixels: D = 1440×960, M = 960×640, L = 2560×1440.
- Root agent exclusively owns live app. Source inventory and isolation research are delegated without live app access.
- Existing user resources are read-only; mutations/destructive tests require disposable fixtures or an isolated profile. Captures containing real session content remain ignored/private.
- Current Settings/Skills mutation checks run in an isolated profile. Replay, Exact Capture, Config Injector, MCP and alerts were enabled there only, after the task-owner manifest and exact live home were verified. No SDK connection/provider request occurred; OS notifications/taskbar flash were disabled for the in-app alert test. Invalid width was restored to 1600; disposable pricing overrides were removed and the tested default rate restored from 99 to 5. Logging was restored from Warn to Info. Wizard bypass testing's invalid home was recovered to the valid fixture home before rebuilding 74 sessions; the duplicate-asset test's 53-byte fixture was restored immediately from its task-owned backup.
- Initial sandbox launch failed with Vite `spawn EPERM`; documented launcher retried with process permissions. This is an execution-environment limitation, not a product finding.
